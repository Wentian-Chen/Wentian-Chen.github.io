    lerobot_converter

    项目简介

    lerobot_converter 是一个任意数据集转换至 LeRobot 格式的轻量级框架， 旨在将来自不同来源的数据集高效、灵活地转换为 Hugging Face 官方的 LeRobotDataset 格式，并已开源在 GitHub 上。

    在机器人控制与 Vision-Language-Action (VLA) 模型的开发过程中，数据准备 往往是最折磨人的一环。将各种来源的数据（如自定义 HDF5、RLDS）转换为 Hugging Face 官方的 LeRobotDataset 格式，常常伴随着内存爆炸和满天飞的 硬编码规则。lerobot_converter 正是为解决这些问题而设计。

    随着 LeRobot 生态的普及，越来越多的团队希望将自己的数据接入官方标准 格式，但格式转换本身并不产生研究价值，却要消耗大量的开发时间。 lerobot_converter 的目标，就是把这段"无用功"压缩到最小。

    项目背景

    内存爆炸：一次性读入的代价

    传统的转换工具往往采用一次性读入整份数据集的方式，将全部数据加载到 内存后再统一处理。对于大规模机器人数据集而言，这会导致内存占用急剧 膨胀，轻则拖慢转换速度，重则直接导致进程崩溃。数据规模越大，这一问题 的代价就越难以承受。

    硬编码规则：改一处、崩一片

    不同的采集设备、不同的数据来源，其格式约定往往各不相同。官方或现有的 转换工具通常将源数据的解析规则硬编码在框架内部，用户面对新的数据来源 时，只能修改框架源码，破坏框架的通用性，还容易引入难以排查的隐藏问题。

    转换过程不可控

    数据转换并非简单的格式搬运：字段命名、数据类型、feature 结构等都需要 按目标格式重新对齐。在缺乏灵活接口的情况下，用户难以在转换过程中插入 自定义逻辑（如指令增强、数据筛选），限制了数据集的二次开发空间。

    正是基于以上痛点，我开发并开源了 lerobot_converter，让数据集的二次 开发和转换变得像搭积木一样轻松。

    设计理念

    lerobot_converter 致力于打造一个可扩展的数据集转换器框架，它的核心 设计理念是：把脏活累活封装好，把最大的自由度留给用户。

    框架将"格式适配"与"数据转换"解耦：繁琐的读取、写入与格式规范化工作 由框架统一承担，用户则专注于自己最关心的业务逻辑。这样既避免了重复 造轮子，又保留了充分的定制空间——用户可以针对任意来源的数据编写自己 的适配层，而无需理解 LeRobotDataset 内部的复杂格式细节。

    "搭积木"的比喻包含两层含义：一是框架提供了标准化的积木块，用户不必 从零搭建；二是用户可以自由选择组合方式，按需接入自己的处理逻辑。 可扩展性因此成为框架的第一设计原则。

    这样的设计带来了两个直接收益：一方面，框架本身保持轻量，学习与上手 成本低；另一方面，用户积累的适配逻辑可以跨项目复用，随着接入的源 格式越来越多，转换成本会持续摊薄。

    传统转换方式与 lerobot_converter 的对比：

    维度 传统转换方式 lerobot_converter
    数据读取 一次性读入，易内存爆炸 迭代式读取，按 episode / frame 处理
    源格式适配 硬编码在框架内 用户自定义适配层
    自定义逻辑 难以插入 读取 + 映射 + feature 对齐均可定制
    输出格式 参差不齐 官方标准 LeRobotDataset
    VLA 任务支持 通常需要二次加工 内置指令增强机制

    核心特点

    lerobot_converter 围绕"通用、轻量、可扩展"三个关键词设计，具体表现 为以下四个核心特点。

    输入包容性强

    支持任意来源（HDF5、RLDS、自定义格式）。无论是官方框架导出的数据， 还是自研采集系统产出的私有格式，都可以接入统一转换流程。输入端的 开放性保证了框架能够长期复用，不会因数据源变化而失效。

    职责分明

    用户只需专注于"读取 + 映射 + feature 对齐"，框架负责生成官方标准 LeRobotDataset。用户不需要关心目标格式的内部细节，框架保证输出的 规范性与一致性。职责边界清晰，团队协作时各司其职，减少相互干扰。

    极致轻量

    采用迭代式读取机制进行数据转换，按 episode 甚至 frame 级别处理数据， 彻底告别一次性读入造成的内存爆炸问题。即使面对远超内存容量的数据集， 也能稳定完成转换。内存占用保持恒定，让转换任务可以放心交给后台长期 运行。

    VLA 任务友好

    内置任务指令增强（Instruction Augmentation）机制，非常适合训练视觉- 语言-动作模型。转换过程即可完成指令层面的数据扩充，为下游训练提供 更丰富的样本，省去了训练前的单独扩增步骤。

    框架结构

    框架的整体处理流程为"输入 → 过程 → 输出"三段式结构：

    • 输入：任意来源（HDF5、RLDS、自定义格式）
    • 过程：用户做"读取 + 映射 + feature 对齐"
    • 输出：官方 LeRobotDataset

    处理流程示意：

    ┌──────────────┐    ┌───────────────────────────┐    ┌──────────────────┐
│     输入      │    │           过程             │    │      输出         │
│ HDF5 / RLDS  │──▶│  读取 + 映射 + feature 对齐  │──▶│  LeRobotDataset  │
│ 自定义格式    │    │   （用户负责，框架兜底）      │    │   （官方标准格式）  │
└──────────────┘    └───────────────────────────┘    └──────────────────┘

    各阶段职责说明：

    • 输入阶段：框架提供统一的读取入口，接受任意来源的数据，用户只需 描述源数据的读取方式。
    • 处理阶段：用户实现数据读取、字段映射与 feature 对齐逻辑，框架 负责调用迭代式读取机制，逐 episode、逐 frame 地推进处理流程。
    • 输出阶段：框架将处理结果封装为官方标准 LeRobotDataset，并保证 输出格式与 Hugging Face 官方规范一致。

    三个阶段的边界清晰，用户介入的深度可以自由选择：简单场景下只需提供 最基本的映射关系，复杂场景下则可以在处理阶段加入完整的自定义逻辑。

    !!! tip "技巧"

    得益于迭代式读取机制，即使是远大于内存容量的原始数据集，也能按
episode 或 frame 粒度逐个处理，转换过程的内存占用始终保持在一个
稳定且可控的水平。

    快速上手思路

    整个转换过程可以按以下思路组织，无需理解目标格式的内部细节：

    1. 明确源数据格式，梳理需要迁移的字段清单；
    2. 按框架约定的方式描述源数据的读取逻辑；
    3. 建立源数据字段与目标 feature 之间的映射关系；
    4. 如有需要，定义 feature 对齐与指令增强等自定义处理；
    5. 运行转换任务，框架按迭代式机制逐步产出数据；
    6. 校验输出的 LeRobotDataset 是否符合预期。

    !!! tip "技巧"

    建议先以少量 episode 验证全流程，确认输出结构与预期一致后，再启动
全量转换，避免重复修正浪费时间。

    常见问题

    围绕使用中反馈较多的几个问题，整理如下。

    转换大文件时内存占用过高怎么办？

    框架内置的迭代式读取机制默认按 episode 甚至 frame 粒度处理数据，内存 占用保持恒定。若仍遇到资源问题，可检查处理阶段是否引入了额外的一次性 加载逻辑。

    遇到不支持的源格式怎么办？

    框架本身不对源格式做硬编码限制，只要按"读取 + 映射 + feature 对齐" 的方式提供对应逻辑，即可接入任意来源的数据。

    转换结果与预期不符怎么办？

    优先核对源数据的字段含义与 feature 对齐逻辑，大部分问题源于映射关系 的疏漏。建议在转换前先抽取少量数据做试点验证，再全量运行。

    指令增强会影响原始数据吗？

    不会。任务指令增强在转换过程中对指令文本进行扩充，原始数据保持不变， 增强逻辑完全由用户按需启用与控制。

    适用场景

    无论是个人的科研实验，还是团队的规模化数据管线，lerobot_converter 都能在数据准备环节发挥作用。典型的使用场景如下。

    VLA 模型训练数据准备

    将自采数据或第三方数据统一转换为 LeRobotDataset，直接接入 LeRobot 等训练流程，省去格式适配的重复劳动。

    数据集格式迁移

    将历史积累的自定义 HDF5、RLDS 数据迁移到官方标准格式，实现新旧数据 体系的平滑过渡，便于后续统一管理与发布。

    多来源数据融合

    当需要将多个不同来源的数据集合并训练时，先统一转换为标准格式，再 合并使用，保证数据语义与结构的一致性。

    数据集二次开发

    在转换过程中加入任务指令增强等自定义处理，按需改造数据内容，实现 数据集的个性化加工。

    !!! warning "注意"

    转换结果的质量取决于用户提供的映射与 feature 对齐逻辑，建议在转换
前充分核对源数据的字段含义，避免出现数据错位或语义偏差。

    总结

    lerobot_converter 从数据准备这一最容易被忽视、却又最耗费精力的环节 入手，用"轻量 + 可扩展"的设计思路，把任意来源的数据统一到官方标准 格式，为机器人控制与 VLA 模型的开发扫清了数据层面的障碍。框架遵循 "把脏活累活封装好，把最大的自由度留给用户"的理念，希望每一位使用者 都能把精力放在真正重要的算法与系统上，而不是与数据格式纠缠。

    如果你也在为数据转换头疼，欢迎试用并参与贡献。框架的迭代方向与路线图 也会在仓库中持续同步。
